Hallazgos reproducibles

P2 · medioResponsive / UX

BUG-001 · Scroll horizontal a 320 px

Área: navegación y todas las páginas

Descripción: En 320×740, body conserva un ancho mínimo de 360 px. El documento se desborda 40 px y obliga a desplazamiento horizontal, ocultando parte del contenido.

Pasos:

  1. Abrir /.
  2. Navegar a Animais.
  3. Emular 320×740.
  4. Observar que documentElement.scrollWidth es 360 px para un viewport de 320 px.

Red: GET iniciales 200. Consola: limpia.

P2 · medioFuncional / validación

BUG-002 · Nombre con espacios crea una ficha fantasma

Área: alta de animales

Descripción: El cliente aplica trim() pero agrega el animal al estado y muestra éxito antes de validar el nombre. La API rechaza el valor con HTTP 400; la respuesta no se gestiona y queda una ficha sin nombre durante la sesión. Al recargar desaparece.

Pasos:

  1. En Animais, abrir “Novo animal”.
  2. Escribir tres espacios en Nome y enviar.
  3. Observar el contador aumentado, una ficha sin nombre y el aviso de éxito.
  4. Revisar Network: POST /api/animals → 400 Bad Request; recargar para ver que no persistió.

Consola/red: 1 error de recurso por el HTTP 400. El servidor responde “O nome é obrigatório.”, pero la UI no lo muestra.

P2 · medioAccesibilidad / teclado

BUG-003 · Escape no cierra el diálogo

Área: formularios

Descripción: El diálogo no escucha la tecla Escape, por lo que una interacción de teclado común no permite cerrar el formulario.

Pasos:

  1. Abrir el formulario de alta de animal.
  2. Pulsar Escape.
  3. El diálogo permanece abierto y el foco sigue en el campo.

Red: sin solicitudes nuevas. Consola: limpia.

P2 · medioAccesibilidad / teclado

BUG-004 · El foco escapa del diálogo

Área: formularios

Descripción: La secuencia Tab alcanza controles de la página que quedan detrás del diálogo. No hay focus trap ni restauración automática del foco al cerrar.

Pasos:

  1. Abrir el formulario de alta de animal.
  2. Pulsar Tab sucesivamente hasta pasar el botón de envío.
  3. El foco llega al botón “Fechar aviso” fuera del diálogo.

El diálogo expone role=dialog y aria-modal=true, pero el foco no queda limitado.

P2 · medioFuncional / errores de red

BUG-005 · Errores de API conservan altas y cambios optimistas

Área: altas, gastos y etapas

Descripción: Los handlers actualizan la UI antes de confirmar las escrituras, ignoran respuestas HTTP no-2xx y no revierten estado ni presentan error. Con POST de gastos o PATCH de etapa rechazados, el usuario ve datos/estado que no están guardados. También aplica al PUT de edición.

Pasos:

  1. Simular HTTP 500 para POST /api/expenses, enviar un gasto y observar que se agrega localmente y se cierra el diálogo.
  2. Simular HTTP 500 para PATCH /api/animals/:id/stage, avanzar una etapa y observar que el badge cambia igualmente.
  3. Recargar: los cambios no existen en el servidor.

Evidencia: los casos BUG-005/005b lo reproducen con respuestas mockeadas; no se escribieron datos en MySQL.
